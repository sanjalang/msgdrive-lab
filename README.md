# 暫時的測試頁:實測步驟

這個 repo 只放一個手動的瀏覽器實驗頁,測完就會刪除。頁面用到的內容全部是程式產生的假資料(虛構資料),沒有任何真實資料、金鑰或權杖;你在頁面上選的檔案只在自己的裝置上讀取,不會上傳。

這份是給使用者照著做的清單。測試頁只用程式產生的假資料(虛構資料)與你自己選的檔案;檔案不會離開裝置,紀錄裡沒有檔名。

- **網址**:<https://sanjalang.github.io/msgdrive-lab/>
- **手機上看這份步驟**:同一份內容也放在 <https://github.com/sanjalang/msgdrive-lab>(repo 首頁)。

## 每次開始之前

1. **重新整理頁面**(Safari 下拉重新整理;主畫面 App 要從多工畫面整個滑掉再開)。新版頁面的 e 區塊第一排有三個選單,第三個是「速度不限」;沒有看到就是還在舊版,再重新整理一次。
2. 頁面最下面是「測試紀錄」。**做完一段就按「複製測試紀錄」貼給我**,並註明是 Safari 還是主畫面 App。
3. 新版的紀錄會保留到下一次開啟:頁面被系統重新載入(通常是記憶體不夠)之後,上一次的紀錄還在,中間多一行 `the page was loaded again here`。所以**遇到頁面自己重新載入,不要按「清除」,直接複製紀錄給我**。
4. 要開始新的一輪時才按「清除」。

## 步驟一:iPhone Safari,剩下的確認

已經知道的(2026-11-12):

- **串流下載(做法 A、B)在 iPhone 上不可靠**:
  - 速度不限的 1 GiB:三次都在 768 到 960 MiB 被收掉。
  - 限速每秒 32 MiB 的 1 GiB:成功一次。
  - 限速的 2 GiB:失敗兩次(896 MiB、1,920 MiB)。
  - 限速的 1 GiB、看到「要下載嗎」先不按:頁面在 960 MiB 被收掉。也就是**使用者還沒按下載的時候,資料會一直堆在記憶體**。
- **做法 C 的下載連結(C2b)可以用**:1 GiB 存下來了,內容正確,而且和你按得快或慢無關。
- 做法 C 的分享(C2a)在 1 GiB 會讓頁面被收掉;做法 C 寫 5 GiB 會失敗。**這兩個不要再試。**
- 暫存空間是空的(C4 列出 0 個項目),但瀏覽器仍回報這個網站用了 15 GiB。

所以 iPhone 的大檔案下載打算用做法 C;它在主畫面 App 裡也可以用(步驟二)。剩下要確認的是它的上限,以及「已用空間暴增」有沒有辦法避免(步驟二的測試一,**最重要**)。

e 區塊的三個選單依序是:**大小**、**資料來源**、**速度**。

### 測試零:iPhone 設定裡的數字(一分鐘)

到 iPhone 的 **設定 → 一般 → iPhone 儲存空間 → Safari**,把「網站資料」(或「文件與資料」)的大小告訴我。

**先不要在設定裡清除網站資料**:測試頁和正式網站在同一個網域,清除會把正式網站在這支手機上的登入狀態、本機的設定和還沒同步的內容一起清掉。要不要清、怎麼清,等我看過數字再說。

### 測試一:做法 C 的下載連結,2 GiB

1 GiB 已經確認過。2 GiB 上次有按、頁面沒事,但檔案沒有比對。

1. 先把「檔案」App 裡舊的 `l0-dl-….bin` 刪掉(騰出空間,也避免選錯)。
2. 第一個選單選 **2 GiB**。
3. 按 **「C1. 產生並寫入」**,等狀態列顯示「已寫入 2048 MiB」(進度跑完後還會等幾秒到十幾秒)。
4. **跳過 C2a**,按一次 **「C2b. 用下載連結儲存」**;出現「要下載嗎」就按下載,等下載圖示跑完。
5. 到 **f 區塊**選存下來的檔案按「開始」,看是不是「一致」。
6. 按 **「C3. 刪除暫存檔」**,再按 **C4**,然後按「複製測試紀錄」貼給我。

手機空間:這個測試會暫時佔兩份,共約 4 GiB。

### 測試二(有空再做):2 GiB 限速,詢問一出現就馬上按下載

這個測試只是要知道「馬上按」的話串流能不能用;不管結果如何,大檔案都會用做法 C,所以不急。

1. 先重新整理頁面:「B. 用隱藏框架下載」旁邊有一顆 **「我剛按了『下載』」**。
2. 第一個選單選 **2 GiB**,第三個選單選 **限速每秒 32 MiB**。
3. 按 **「B. 用隱藏框架下載」**;「要下載嗎」一出現,**馬上按下載**(3 秒內),接著馬上按頁面上的「我剛按了『下載』」。
4. 頁面留在前景等約 70 秒。
5. 記下有沒有走到「瀏覽器讀完了」、頁面有沒有自己重新載入;有檔案就到 f 區塊比對。
6. 按「複製測試紀錄」貼給我。

## 步驟二:iPhone 主畫面 App(現在最需要的)

已經知道的(2026-11-12):

- **做法 C 的下載連結在主畫面 App 裡可以用**:256 MiB 與 1 GiB 都存下來了,比對內容一致;回到測試頁時頁面還在。
- 按 C2b 之後出現的是一個檔案檢視畫面(檔案圖示、檔名、「Open in …」、「More…」),不是「要下載嗎」。
- 瀏覽器回報的已用空間會暴增:寫一個 256 MiB 的檔案就多了 8,320 MiB,寫完 1 GiB 之後回報 67,400 MiB(實際上暫存空間是空的)。看起來是瀏覽器每寫一段就把整個檔案的大小再算一次。

**不要按「A. 下載」**(會離開頁面而且回不來)。

### 測試一:比較寫入方式(C5,最重要)

要找一種不會讓「已用空間」暴增的寫法。為了讓數字從 0 開始,要先把主畫面上的測試頁刪掉重加。

1. 長按主畫面上的測試頁圖示 → **刪除**(它的資料會一起清掉;正式網站的主畫面 App 不受影響)。
2. 用 Safari 開測試頁,先重新整理一次,確認做法 C 那一排有 **「C5. 比較寫入方式」**。
3. Safari 的分享選單 → **加入主畫面**,然後從主畫面開啟。
4. **什麼都先不要按**,直接按 **「C5. 比較寫入方式」**,等約 20 秒,狀態列顯示「寫入方式比較完成」。
5. 按 **「C4. 列出暫存空間」**。
6. 按「複製測試紀錄」貼給我。

### 測試二:兩個問題(用說的就好)

1. 在那個檔案檢視畫面,你是按哪裡把檔案存到「檔案」的?(底部的分享圖示 → 儲存到檔案,還是 More…,還是別的)
2. 回到 f 區塊比對時,選的是剛剛才存下來的那個檔案嗎?(「檔案」裡可能還有先前 Safari 測試留下的同名檔案)

### 測試三:其他項目(有空再做)

1. **c 區塊**:按「1. 正確性」(應為 64/64)→ 選 256 MiB 按「2. Worker 裡算」。
2. **f 區塊**:選一個 1 GiB 以上的影片 → 按「開始」→ 等到「完成」。
3. **e 區塊,256 MiB、速度不限**:按「B. 用隱藏框架下載」,記下畫面上出現什麼、有沒有存到檔案。
4. 複製測試紀錄貼給我。

## 步驟三:桌機 Chrome,寫入真的資料夾(實驗 g)

用你自己的 Chrome 分頁開同一個網址(這一步的系統對話框不能由自動操作代按)。

1. g 區塊選 1 GiB → 按「選資料夾並寫入」→ 選一個空的資料夾(要測外接硬碟就選外接硬碟上的資料夾)→ 允許寫入。
2. 等到狀態列顯示「內容正確;測試檔已刪除」。
3. 改選 5 GiB 再做一次(磁碟要有 5 GiB 以上的空間)。
4. (有空再做)中途取消:再開始一次 5 GiB,寫到一半把分頁關掉,看資料夾裡留下什麼。預期只有一個 `.crswap` 暫存檔,沒有 `l0-write-….bin`;留下的檔案手動刪除。
5. 複製測試紀錄貼給我。

## 步驟四:正式網站上的串流播放(web 0.6.1,2026-11-12 部署)

這一步在**正式網站**上做,不是測試頁。0.6.1 起,Google Drive 模式下 8 MiB 以上的影片與音訊,在預覽裡會邊下載邊播放;其他情況(Dropbox、本機資料夾、8 MiB 以下)和以前一樣。桌機 Chrome 已經實測過,iPhone 還沒有。

需要:資料放在 Google Drive 的資料夾,而且裡面有一部 8 MiB 以上的影片(沒有的話,先在某個頻道貼一部,等它同步完)。

1. 先確認版本:設定頁最下面的版本號是 **0.6.1**。不是的話重新整理(主畫面 App 要整個滑掉再開)。
2. 打開那部影片的預覽。記下:
   - 從點開到可以播放大約幾秒;
   - 有沒有顯示「無法播放」或「讀取檔案失敗」。
3. 播放 10 秒左右,然後把進度條拖到中間、再拖到接近結尾。記下每次拖完大約幾秒後繼續播。
4. 播放中切到別的 App 約 10 秒再回來,看能不能接著播(或按播放後能繼續)。
5. 關掉預覽,再打開一次,確認還能播。
6. Safari 與主畫面 App 各做一遍。

怎麼知道是不是真的在串流:大影片(例如 50 MB 以上)在以前要等整個下載完才開始播,現在應該幾秒內就能播,而且拖曳到沒看過的位置要等一下。如果某個瀏覽器不能串流,程式會自動退回以前的做法(整個下載完才播),這時起播會明顯變慢,也請告訴我。

回報時只要說:哪個瀏覽器、影片大約多大、起播幾秒、拖曳幾秒、有沒有錯誤訊息。

## 全部做完之後

- iPhone:「檔案」App 裡的 `l0-dl-….bin` 全部刪掉;測試頁按「C3. 刪除暫存檔」;主畫面上的測試頁圖示可以移除。
- GitHub:把 `sanjalang/msgdrive-lab` 整個刪掉(它和正式網站在同一個網域底下,不該久留)。

## 紀錄裡的字怎麼看(不必看懂也可以直接貼)

| 開頭 | 意思 |
|---|---|
| `c.check` / `c.worker` | 雜湊的正確性與速度 |
| `f.picked` | 選了檔案;`sincePickerOpened` 是從點選到拿到檔案的時間 |
| `f at=…` / `f done` | 分段讀取的進度與結果 |
| `f.compare-with-generated … SAME` | 這個檔案和測試頁產生的內容一致 |
| `e.click` / `e.frame` | 按了做法 A / 做法 B |
| `e.start` → `e.progress` → `e.done` | 瀏覽器開始讀、讀到哪裡、讀完了(讀完不等於存好了) |
| `e.cancel` / `e.error` | 瀏覽器中途不讀了 / 出錯 |
| `e.user confirmed-download` | 你按了「我剛按了『下載』」;`sinceFrame` 是從按 B 到這時的秒數 |
| `e.stage …` | 做法 C 的寫入、分享、下載連結 |
| `e.stage entry` / `e.stage list` | C4 列出的暫存空間:每個項目的大小、總和、瀏覽器回報的已用空間 |
| `e.method …` | C5 比較寫入方式:每一種寫法讓回報的已用空間增加多少(`added`) |
| `page visibility=hidden` | 頁面被切到背景 |
| `the page was loaded again here` | 頁面被重新載入(上面是重新載入之前的紀錄) |
