# 暫時的測試頁:實測步驟

這個 repo 只放一個手動的瀏覽器實驗頁,測完就會刪除。頁面用到的內容全部是程式產生的假資料(虛構資料),沒有任何真實資料、金鑰或權杖;你在頁面上選的檔案只在自己的裝置上讀取,不會上傳。

這份是給使用者照著做的清單。測試頁只用程式產生的假資料(虛構資料)與你自己選的檔案;檔案不會離開裝置,紀錄裡沒有檔名。

- **網址**:<https://sanjalang.github.io/msgdrive-lab/>
- **手機上看這份步驟**:同一份內容也放在 <https://github.com/sanjalang/msgdrive-lab>(repo 首頁)。

## 每次開始之前

1. **重新整理頁面**(Safari 下拉重新整理;主畫面 App 要從多工畫面整個滑掉再開)。新版頁面的 e 區塊第一排有三個選單,第三個是「速度不限」;沒有看到就是還在舊版,再重新整理一次。
2. 頁面最下面是「測試紀錄」。**做完一段就按「複製測試紀錄」貼給我**,並註明是 Safari 還是主畫面 App。
3. 新版的紀錄會保留到下一次開啟:頁面被系統重新載入(通常是記憶體不夠)之後,上一次的紀錄還在,中間多一行 `the page was loaded again here`。所以**遇到頁面自己重新載入,不要按「清除」,直接複製紀錄給我**。
4. 要開始新的一輪時才按「清除」。

## 步驟一:iPhone Safari(已有結論;只剩一個有空再做的確認)

結論:

- **串流下載在 iPhone 上不能用來下載大檔案**:使用者還沒按「下載」的時候,Safari 照樣一直讀,資料堆在記憶體,堆到 0.75 到 1 GiB 頁面就被系統收掉;限速也救不了。
- **做法 C 的下載連結可以用**:先寫進瀏覽器內部儲存空間,再用下載連結交給系統。
- 分享(C2a)在 1 GiB 會讓頁面被收掉。**1 GiB 以上不要按 C2a,也不要再做「速度不限」的 1 GiB。**

### 有空再做:Safari 裡用新的寫入方式下載 2 GiB

主畫面 App 已經驗證到 5 GiB;這一項只是確認 Safari 分頁裡也一樣。

1. 用 Safari 開測試頁並重新整理,確認做法 C 那一排上面有 **「寫入方式:Worker 同步寫入(新)」**。
2. 先把「檔案」App 裡舊的 `l0-dl-….bin` 刪掉。
3. 第一個選單選 **2 GiB** → 按 **C1** → 等到「已寫入 2048 MiB」→ 按 **C2b** → 出現「要下載嗎」就按下載,等下載圖示跑完。
4. 到 **f 區塊**選存下來的檔案按「開始」,看是不是「一致」。
5. 按 **C3**,再按 **C4**,然後按「複製測試紀錄」貼給我。

## 步驟二:iPhone 主畫面 App(已完成)

結論:

- **做法 C 的下載連結在主畫面 App 裡可以用,驗證到 5 GiB**,內容都正確。
- 按下載連結之後出現的是檔案檢視畫面:按底部的**分享圖示 → 儲存到檔案**,存好後關掉檢視畫面就回到 App,頁面還在。
- 寫入要用 **Worker 同步寫入**:舊的寫法每寫一段就把整個檔案的大小再算進已用空間(寫 256 MiB 多 8,320 MiB),而且 5 GiB 寫不完;新的寫法沒有這些問題。
- 瀏覽器回報的已用空間在刪除暫存檔後不會下降,要把 App 滑掉重開才歸零。

不用再測。測試頁用完之後,可以把主畫面上的測試頁圖示刪掉(它的暫存資料會一起清掉)。

## 步驟三:桌機 Chrome,寫入真的資料夾(實驗 g)

用你自己的 Chrome 分頁開同一個網址(這一步的系統對話框不能由自動操作代按)。

1. g 區塊選 1 GiB → 按「選資料夾並寫入」→ 選一個空的資料夾(要測外接硬碟就選外接硬碟上的資料夾)→ 允許寫入。
2. 等到狀態列顯示「內容正確;測試檔已刪除」。
3. 改選 5 GiB 再做一次(磁碟要有 5 GiB 以上的空間)。
4. (有空再做)中途取消:再開始一次 5 GiB,寫到一半把分頁關掉,看資料夾裡留下什麼。預期只有一個 `.crswap` 暫存檔,沒有 `l0-write-….bin`;留下的檔案手動刪除。
5. 複製測試紀錄貼給我。

## 步驟四:正式網站上的串流播放(web 0.6.1,2026-11-12 部署)

這一步在**正式網站**上做,不是測試頁。0.6.1 起,Google Drive 模式下 8 MiB 以上的影片與音訊,在預覽裡會邊下載邊播放;其他情況(Dropbox、本機資料夾、8 MiB 以下)和以前一樣。桌機 Chrome 已經實測過,iPhone 還沒有。

需要:資料放在 Google Drive 的資料夾,而且裡面有一部 8 MiB 以上的影片(沒有的話,先在某個頻道貼一部,等它同步完)。

1. 先確認版本:設定頁最下面的版本號是 **0.6.1**。不是的話重新整理(主畫面 App 要整個滑掉再開)。
2. 打開那部影片的預覽。記下:
   - 從點開到可以播放大約幾秒;
   - 有沒有顯示「無法播放」或「讀取檔案失敗」。
3. 播放 10 秒左右,然後把進度條拖到中間、再拖到接近結尾。記下每次拖完大約幾秒後繼續播。
4. 播放中切到別的 App 約 10 秒再回來,看能不能接著播(或按播放後能繼續)。
5. 關掉預覽,再打開一次,確認還能播。
6. Safari 與主畫面 App 各做一遍。

怎麼知道是不是真的在串流:大影片(例如 50 MB 以上)在以前要等整個下載完才開始播,現在應該幾秒內就能播,而且拖曳到沒看過的位置要等一下。如果某個瀏覽器不能串流,程式會自動退回以前的做法(整個下載完才播),這時起播會明顯變慢,也請告訴我。

回報時只要說:哪個瀏覽器、影片大約多大、起播幾秒、拖曳幾秒、有沒有錯誤訊息。

## 步驟五:正式網站上的大檔案(web 0.7.1,2026-11-13 部署)

這一步在**正式網站**上做。0.7.0 起,Google Drive 模式可以上傳超過 100 MB 的附件(最大 20 GB),但要先在設定頁打開開關。桌機 Chrome 已經實測過上傳、取消、接續(包含重新整理之後、離開頻道之後)、預覽、影片與音訊的串流、存到裝置(到 1.6 GB,內容比對正確);還沒有的是 iPhone,以及桌機上系統的「另存新檔」對話框本身。

**先知道四件事**:

- **備份還不包含超過 100 MB 的檔案。**備份時會略過它們並列出數量;這些檔案只存在資料夾裡,沒有第二份。所以先用不怕遺失的檔案測。
- 上傳期間要**留在那個頻道**、畫面要開著。切換頻道、開設定頁、按上一頁都會中止上傳(不會有提示);回來重新選同一個檔案再送出,會從中斷的地方接著傳。
- 要用 Google Drive 的資料夾;Dropbox 與本機資料夾的上限仍是 100 MB。
- 「存到裝置」要等的時間幾乎就是下載的時間,手機看當時的網路。0.7.1 起會同時下載幾段:桌機實測 1.6 GB 從 120 秒變成 55 秒;iPhone 上 0.7.0 是 30 秒到 1 分鐘(Wi-Fi),0.7.1 能快多少請測了告訴我。iPhone 寫完之後按連結,系統還會再複製一份到「檔案」App。目前等的時候畫面要開著;之後會改成可以在背景進行。

步驟(Safari 與主畫面 App 各做一遍;桌機只要做第 7 步):

1. 確認版本:設定頁最下面的版本號是 **0.7.1**(0.7.1 起「存到裝置」會同時下載幾段)。不是的話重新整理(主畫面 App 要整個滑掉再開)。
2. 設定頁最下面的「實驗功能」→ 勾選「大檔案」。這個設定只記在這個瀏覽器,Safari 與主畫面 App 要各勾一次。
3. 回到任一個頻道,附上一個 **200 MB 到 1 GB** 的檔案(影片最好,之後可以順便測播放),按送出。記下:
   - 有沒有先出現「正在讀取」再出現「正在上傳」,數字有沒有在動;
   - 大約多久傳完;傳完後訊息有沒有出現。
4. 再傳一個,這次在「正在上傳」到一半時按「取消上傳」。應該出現「已取消上傳…」,文字與附件還在。再按一次送出:應該**沒有**「正在讀取」,直接從剛才的位置接著傳。
5. 再傳一個,傳到一半時把 App 切到背景約 10 秒再回來(或讓螢幕關掉再打開)。看它是繼續傳、停住、還是出現錯誤;停住或出錯的話,再送出一次看能不能接著傳。
6. 點開剛才傳上去的檔案:
   - 影片或音訊:能不能播放、拖曳;
   - 按「下載」:應該出現「存到裝置」的對話框,先顯示進度,寫完後出現一個下載連結。**記下從按下去到連結出現大約幾秒。**按那個連結,照畫面的說明存到「檔案」App(主畫面 App 會先跳到檔案檢視畫面,按分享 → 儲存到檔案,再回來)。到「檔案」App 確認檔案大小正確、打得開。
7. **桌機 Chrome**(只有這一步要在電腦上做,約一分鐘):打開一個超過 100 MB 的附件 → 按「下載」→ 在「另存新檔」的對話框選位置。確認存下來的檔案打得開。寫入、進度與取消都已經自動測過,這一步只是確認系統的對話框本身沒問題。
8. 設定頁 →「備份與還原」→ 開始備份:確認畫面有「有 n 個超過 100 MB 的檔案…不會包含在這份備份裡」那一行。到這裡可以按取消,不必真的備份。

回報時只要說:哪個瀏覽器、檔案大約多大、每一步有沒有照預期、看到什麼錯誤訊息(照抄或截圖)。

## 全部做完之後

- iPhone:「檔案」App 裡的 `l0-dl-….bin` 全部刪掉;測試頁按「C3. 刪除暫存檔」;主畫面上的測試頁圖示可以移除。
- GitHub:把 `sanjalang/msgdrive-lab` 整個刪掉(它和正式網站在同一個網域底下,不該久留)。

## 紀錄裡的字怎麼看(不必看懂也可以直接貼)

| 開頭 | 意思 |
|---|---|
| `c.check` / `c.worker` | 雜湊的正確性與速度 |
| `f.picked` | 選了檔案;`sincePickerOpened` 是從點選到拿到檔案的時間 |
| `f at=…` / `f done` | 分段讀取的進度與結果 |
| `f.compare-with-generated … SAME` | 這個檔案和測試頁產生的內容一致 |
| `e.click` / `e.frame` | 按了做法 A / 做法 B |
| `e.start` → `e.progress` → `e.done` | 瀏覽器開始讀、讀到哪裡、讀完了(讀完不等於存好了) |
| `e.cancel` / `e.error` | 瀏覽器中途不讀了 / 出錯 |
| `e.user confirmed-download` | 你按了「我剛按了『下載』」;`sinceFrame` 是從按 B 到這時的秒數 |
| `e.stage …` | 做法 C 的寫入、分享、下載連結 |
| `e.stage entry` / `e.stage list` | C4 列出的暫存空間:每個項目的大小、總和、瀏覽器回報的已用空間 |
| `e.method …` | C5 比較寫入方式:每一種寫法讓回報的已用空間增加多少(`added`) |
| `page visibility=hidden` | 頁面被切到背景 |
| `the page was loaded again here` | 頁面被重新載入(上面是重新載入之前的紀錄) |
